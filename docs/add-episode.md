# Adding a new episode

How an agent takes one new "Shir ya Khat" recording — from YouTube video / agenda /
transcript — all the way into the committed content bundle the app ships (episode
metadata, bilingual transcript, Claude enrichment, glossary, search index). Follow the
steps in order; every step is idempotent and re-runnable.

Fixing or updating content that is already in the bundle (transcript fixes, chapters,
name corrections)? See [updating-content.md](updating-content.md).

## 0. Mental model

The app ships a **static content bundle** under `content/`, generated by the pipeline in
`pipeline/`. Nothing is fetched at runtime. The flow is:

```
raw corpus (yt-dlp output)         content/ bundle (committed, shipped)
 <stem>.info.json          ─┐      episodes.json        (metadata, chapters, dedup)
 <stem>.en.srt             ─┼─►     transcripts/<id>.json (bilingual cue list)
 <stem>.fa.srt             ─┘      enrichment/<id>.json  (Claude: summary/quotes/glossary/corrections)
 website _posts + RSS              glossary.json         (merged + tap-to-define aliases)
                                   search-index.json     (inverted index)
                                   index.generated.ts    (Metro static require map)
```

Pipeline steps (`pipeline/package.json`), run from repo root:

| script | needs | writes |
|---|---|---|
| `npm run pipeline:build` → `episodes` → `transcripts` → `finalize` | corpus (read-only), website clone, RSS cache | episodes.json, transcripts/, glossary.json, search-index.json, index.generated.ts |
| `npm run pipeline:enrich` | `ANTHROPIC_API_KEY`, corpus transcripts | enrichment/<id>.json, enrichment/manifest.json |

`build-episodes` and `finalize` are pure/offline. `fetch-sources` and `enrich` are the
only network steps. `enrich` is the only step that costs money.

- **Corpus is read-only** — `/Volumes/Beezhan/data/podcasts` (override `SYK_CORPUS_DIR`).
  The pipeline never writes to it; a new episode is added by **placing new raw files there**.
- Episode identity = the `(SxxEyy)` code in the title + the YouTube id in `[...]`.
  Re-uploads/audio mirrors of the same code are deduped into `altYoutubeIds`.

## 1. Ingest the raw recording into the corpus

The corpus is yt-dlp output. For a new episode, produce the **same file set** under
`$SYK_CORPUS_DIR` using one stem. Use yt-dlp with this output template so the stem
carries the title, `(SxxEyy)` code, and `[youtubeId]`:

```bash
cd "$SYK_CORPUS_DIR"   # /Volumes/Beezhan/data/podcasts
yt-dlp \
  -o "%(playlist_index)s - %(title)s [%(id)s].%(ext)s" \
  --write-info-json --write-description --write-thumbnail \
  -x --audio-format mp3 -k \
  "https://www.youtube.com/watch?v=<VIDEO_ID>"
```

Required files for one stem (`<stem>` = filename without extension):

- `<stem>.info.json` — **required**. Must contain `id`, `title` (with the `(SxxEyy)`
  code), `duration`, `upload_date`, and ideally `chapters`, `description`, `thumbnail`,
  `view_count`, `like_count`.
- `<stem>.en.srt` and `<stem>.fa.srt` — **required** bilingual Whisper transcripts
  (see step 2). Without at least one, `build-transcripts` warns and skips the episode.
- `<stem>.mp3` / `<stem>.mp4`, `<stem>.description`, thumbnail — optional but expected.

If the title has **no `(SxxEyy)` code**, add the YouTube id → code mapping to
`EPISODE_CODE_OVERRIDES` in `pipeline/src/config.ts`. If it is **not a regular episode**
(interview, guest spot), add it to `SPECIALS` instead (becomes season 0 / `spNN`).

## 2. Transcribe (Whisper, bilingual)

Generate two SRT tracks from the audio — Persian original and English translation.
Match the existing corpus: `.fa.srt` (transcribe `fa`) and `.en.srt` (translate task).

```bash
# Persian original
whisper "<stem>.mp3" --language fa --task transcribe --output_format srt \
  --output_dir "$SYK_CORPUS_DIR" && mv "<stem>.srt" "<stem>.fa.srt"
# English translation
whisper "<stem>.mp3" --language fa --task translate --output_format srt \
  --output_dir "$SYK_CORPUS_DIR" && mv "<stem>.srt" "<stem>.en.srt"
```

Raw Whisper output is fine — it is **unproofread on purpose**. Proper nouns are garbled
(show name → "Shenakht"; "Tornado Cash" → «تورنیدو کشت»). The enrich step recovers
correct forms and emits `corrections` that `finalize` applies globally. Do **not**
hand-clean SRTs.

## 3. Build metadata + transcripts

From repo root:

```bash
npm run pipeline:fetch-sources   # refresh website clone + RSS cache (network)
npm run pipeline:build           # episodes.json + transcripts/<id>.json + finalize
```

Verify the new episode appeared:

```bash
node -e "const e=require('./content/episodes.json');const x=e.find(x=>x.code==='S07E08');console.log(x? {id:x.id,code:x.code,titleEn:x.titleEn,chapters:x.chapters.length,durationSec:x.durationSec}:'MISSING')"
ls content/transcripts/<id>.json
```

If `! no subtitles for <id>` printed → the `.fa.srt`/`.en.srt` stems don't match
`sourceStem`; fix the corpus filenames.

## 4. Enrich with Claude (summary, quotes, glossary, corrections)

Only this step needs `ANTHROPIC_API_KEY`. It is resumable and idempotent — the manifest
skips finished episodes, so run it scoped to the new id to avoid re-billing the archive.

```bash
export ANTHROPIC_API_KEY="$(cat /Volumes/Beezhan/secrets/anthropic-ttmechanics.txt)"
unset CLAUDE_CODE_OAUTH_TOKEN
npm run pipeline:enrich -- --only <id>      # e.g. --only s07e08
# optional: --batch (50% cheaper, async) ; --force (redo) ; --concurrency N
```

Writes `content/enrichment/<id>.json` with `summaryFa/En`, 3-5 `quotes`, 5-12 `glossary`
terms, and up to 30 `corrections`. Model defaults to `claude-sonnet-4-6`
(`SYK_ENRICH_MODEL` to override). If you change the prompt, bump `PROMPT_VERSION` in
`enrich.ts` so every episode re-enriches.

## 5. Finalize (merge glossary, apply corrections, rebuild indexes)

```bash
npm run pipeline:finalize
```

This merges per-episode glossaries into `content/glossary.json` (with tap-to-define
`aliases` + which `episodes` use each term), applies `corrections` to the transcripts
(idempotent; `UNSAFE_WRONG` words like خط/شیر are never blanket-replaced), rebuilds
`search-index.json`, and regenerates `index.generated.ts`.

### Episode artwork (optional)

The episode screen and the lock screen show a bundled square thumbnail when there is
one. Save it as `assets/episode-thumbs/<CODE>.jpg` (JPEG, at most 640 px on the long
edge) and add the matching line to the map in `src/content/thumbs.ts`. Without it the
episode simply falls back to its YouTube thumbnail.

## 6. Validate

```bash
npm run check        # lint + typecheck + jest (content.test.ts validates the bundle)
npm run pipeline:check   # re-runs finalize; fails if a derived file is stale (CI runs this too)
```

`src/__tests__/content.test.ts` checks the bundle is internally consistent (ids,
transcripts, glossary, search index align). All green = shippable.

## 7. Commit as a PR

Never push to the default branch (repo policy — PRs only). Commit the regenerated bundle:

```bash
git checkout -b content/add-<id>
git add content/ pipeline/src/config.ts   # config.ts only if you touched overrides/specials
git commit -m "content: add <CODE> — <short english title>"
git push -u origin content/add-<id>
gh pr create -R shiryakhat/mobileapp --fill
```

The app picks up the new episode from the committed bundle on the next build — no app
code change is needed for an ordinary episode. Ship a store build only when you want the
new content in the installed app (OTA `eas update` also works for JS/content-only
changes; see `docs/release.md`).

## Checklist

- [ ] Raw files in corpus: `<stem>.info.json` + `.fa.srt` + `.en.srt` (+ mp3/thumb)
- [ ] `(SxxEyy)` code present, or added to `EPISODE_CODE_OVERRIDES` / `SPECIALS`
- [ ] `pipeline:build` → episode in `episodes.json`, transcript written, no "no subtitles" warning
- [ ] `pipeline:enrich --only <id>` → `enrichment/<id>.json` exists
- [ ] `pipeline:finalize` → glossary/search-index/index.generated refreshed
- [ ] Optional: `assets/episode-thumbs/<CODE>.jpg` + its line in `src/content/thumbs.ts`
- [ ] `npm run check` and `npm run pipeline:check` green
- [ ] PR opened against `shiryakhat/mobileapp`
