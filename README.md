# Shir ya Khat — mobile app

Bilingual (Farsi / English), RTL-first archive and community app for **Shir ya Khat** (شیر یا خط,
"Heads or Tails"), a non-profit Persian blockchain podcast recorded as live panels since 2017.

- **Expo SDK 58**, React Native 0.88, TypeScript (strict), expo-router
- **Dark-first** custom design system, Vazirmatn typeface for both scripts
- **Farsi is the default** (full RTL); English is one tap away and needs no app reload
- **No backend required**: the app launches and navigates from the committed `content/` bundle

## What is in v1

| Area       | What it does                                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Episodes   | 41 episodes grouped by season, bilingual cards, Jalali dates in Farsi, continue-listening card                                               |
| Player     | Video (YouTube) / audio (podcast RSS) toggle, background audio with lock-screen controls, resume per episode, chapter markers, speed control |
| Transcript | Bilingual, synced to playback, tap a line to seek, long-press to bookmark / share / copy                                                     |
| Search     | Full-archive search over every transcript (FA + EN) returning episode + timestamp hits                                                       |
| Glossary   | 358 crypto terms with FA + EN definitions; tap-to-define inline in transcripts                                                               |
| Bookmarks  | Per episode and per timestamp, local-first                                                                                                   |
| Downloads  | Resumable offline audio downloads with storage management                                                                                    |
| Offline    | Thumbnails, artwork and community lists are cached on disk; Settings → Storage shows usage and clears the cache (never downloads)            |
| Share      | On-device image card (art + quote + QR) and plain quote + link sharing                                                                       |
| Community  | Supabase schema, GitHub sign-in, minute comments, questions, bookmark sync — **flagged off**                                                 |

Project status — what is shipped, what is flag-gated off, and what must change before community
features are enabled — is tracked in [docs/STATUS.md](docs/STATUS.md). The store listing copy is in
[docs/store-listing.md](docs/store-listing.md).

## Quick start

```bash
npm install
npm start          # then press i (iOS simulator), a (Android) or scan the QR with Expo Go
```

No `.env` is needed. Everything the app shows is read from `content/`.

```bash
npm run check      # lint + typecheck + tests (what CI runs)
npm run format     # prettier
```

Deep links (scheme `shiryakhat://`):

| Link                                          | Opens                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------- |
| `shiryakhat://episode/s07e07?t=600`           | An episode at 10:00                                                                   |
| `shiryakhat://episode/s07e07?pane=transcript` | An episode on its transcript (`about`, `chapters`, `transcript`)                      |
| `shiryakhat://?tab=search&q=tornado`          | Search with a query (`tab` = `episodes`, `search`, `glossary`, `library`, `settings`) |

## Media strategy

Nothing heavy is re-hosted.

- **Video** streams from YouTube by video id.
- **Audio** streams from the podcast's public RSS enclosures (all 40 regular episodes are matched by
  episode code). The one special without an RSS item falls back to YouTube for audio.
- **Thumbnails** are YouTube thumbnail URLs.

The corpus holds 49 videos for 40 episodes plus one special, because seasons 4 to 6 were uploaded
twice. The pipeline de-duplicates by episode code, prefers the upload that has chapters and then the
original upload, and keeps the others in `altYoutubeIds`.

## RTL

Direction is set with the `direction` style on every screen root (`components/ui/Screen`), driven by
the persisted locale, so the whole UI mirrors instantly when the language changes.

- `Text` takes logical alignment (`start` / `end`) and a per-line `dir`, so an English line inside the
  Farsi UI keeps its own paragraph direction.
- The playback timeline, transport controls and progress bars are pinned left-to-right in every
  locale, as on the system players.
- Directional icons mirror; others do not.
- Mixed-direction metadata such as `S07E07 · ۱۹ مرداد ۱۴۰۴` is joined with Unicode isolates.
- `src/__tests__/rtl.test.tsx` pins these rules down.

## Content pipeline

```bash
cd pipeline && npm install
```

| Step          | Command                 | Needs               | Output                                                              |
| ------------- | ----------------------- | ------------------- | ------------------------------------------------------------------- |
| Fetch sources | `npm run fetch-sources` | network             | `pipeline/.cache/website`, `pipeline/.cache/rss.xml`                |
| Episodes      | `npm run episodes`      | corpus, cache       | `content/episodes.json`                                             |
| Archive.org   | `npm run archive`       | network             | archive.org fallback URLs in `content/episodes.json`                |
| Transcripts   | `npm run transcripts`   | corpus              | `content/transcripts/*.json`                                        |
| Enrichment    | `npm run enrich`        | `ANTHROPIC_API_KEY` | `content/enrichment/*.json`                                         |
| Finalize      | `npm run finalize`      | nothing             | glossary, corrected transcripts, search index, `index.generated.ts` |

`npm run check:content` re-runs finalize and fails if any committed derived file changes; CI runs
it on every PR. Adding an episode: [docs/add-episode.md](docs/add-episode.md). Fixing or updating
existing content: [docs/updating-content.md](docs/updating-content.md).

`npm run build` runs episodes, transcripts and finalize. The raw corpus
(`/Volumes/Beezhan/data/podcasts`, override with `SYK_CORPUS_DIR`) is read-only and never copied.

**Enrichment** sends each episode's bilingual transcript to Claude (`claude-sonnet-4-6`, override
with `SYK_ENRICH_MODEL`) and gets back a bilingual summary, 3 to 5 timestamped key quotes, glossary
terms, and a list of mis-transcribed names and terms. It is resumable: `manifest.json` records
finished episodes and re-running skips them.

```bash
npm run enrich                          # everything still pending, 3 at a time
npm run enrich -- --only s07e07,s07e06  # specific episodes
npm run enrich -- --batch               # Message Batches API (cheaper, asynchronous, resumable)
npm run enrich -- --force               # redo finished episodes
```

**Finalize** is offline and idempotent. It merges glossaries, applies the corrections to the
transcripts (for example the mis-heard show name "Shenakht"), rebuilds the search index and
regenerates the require map Metro uses to load transcripts lazily.

Transcripts are raw Whisper output with automatic name fixes only. They are not proofread, and the
app says so under each transcript.

## Community backend (off by default)

Set these in `.env` once a Supabase project exists (see `supabase/README.md`):

```
EXPO_PUBLIC_COMMUNITY_ENABLED=true
EXPO_PUBLIC_SUPABASE_URL=...
EXPO_PUBLIC_SUPABASE_ANON_KEY=...
```

With the flag off the Supabase SDK is never initialised and the app shows a short note in Settings.

## Build and release

```bash
npx eas-cli build --profile development --platform ios   # dev client for the simulator
npx eas-cli build --profile preview                      # internal builds
```

Pushing a `v*` tag runs `.github/workflows/release.yml`: lint, typecheck and test, then EAS Build
and EAS Submit to TestFlight and the Play internal track. The app version comes from
`package.json` (`app.config.js`), so `npm version patch && git push --follow-tags` is the whole
release command. One-time setup, the secrets table and troubleshooting are in
[`docs/release.md`](docs/release.md).

Background audio and lock-screen controls need a development or store build to behave as they will
in production; Expo Go is fine for everything else.
